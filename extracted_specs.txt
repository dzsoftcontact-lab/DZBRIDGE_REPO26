
DZ-Bridge Detailed Functional Specs 
October 12,2026
General Requirements
DZ-Bridge is a web-based matchmaking platform to connect Algerian experts (local and diaspora) with Algerian organizations for knowledge and technology transfer collaborations.
The DZ Bridge platform core features include:
Trilingual: Arabic, English and French (Automatic translation maybe considered)
Responsive UI: web and mobile friendly
Highly available (cloud infrastructure)
Highly secure especially for confidential information (Experts and Organisations)
Easy to maintain and upgrade
This document is a draft functional specification with UI/UX mockups and workflow descriptions for a DZ-Bridge MVP (Minimum Viable Product).

User Stories
As an expert, I want to create an account so I can offer my expertise.
As an organization, I want to register so I can submit collaboration projects.
As a user, I want secure login/logout functionality. 
As an admin, I want to track profile completion and monitor project outcomes.
As a system, I want to log interactions for analytics.
User Workflows
Workflow 1: Expert Registration and Availability
[Sign-Up] → [Create Profile] → [Upload CV] → [Enter Preferences] → [Post Availability] → [Receive Match Alerts] Sign-Up → Upload CV → AI-Assisted Profile Generation (or Admin Created Profile) → Review/Edit Profile → Verify Profile → Enter Preferences → Post Availability → Receive Match Alerts
Workflow 2: Organization Submits a Project
[Sign-Up] → [Create Org Profile] → [Submit Project] → [Receive Matched Experts] → [Invite Expert] → [Event Setup]
Workflow 3: Match Confirmation and Collaboration
[Match Detected] → [Expert Reviews Offer] → [Confirms Interest] → [Organization Notified] → [Direct Contact and Planning]  Match Detected → User Reviews Match → Express Interest / Accept → Contact Request → Select Available Contact Time → Consent / Acceptance → Private Communication

2. Enters basic info (name, email, password)
3. Receives verification email
4. Completes profile:
Professional details
Expertise areas (multi-select)
Collaboration preferences

6. Profile becomes active for matching
7. Receives match notification
8. Accepts opportunity
9. Organization notified
Use Case 2: Organization Submits Project
1. Org admin Creates profile and logs in
2. Clicks "Submit New Project"
3. Completes project form:
Title and description
Required skills (tags)
Timeline (dates, duration)
Location(s)
Logistics offered (travel, lodging, fees)
4. Submits project for matching
5. System generates matches 
6. Organization receives expert matches within set deadline (1-2 weeks)
7. Reviews expert profiles
8. Initiates contact through platform
9. Collaboration confirmed
Use Case 3: Matching Process
1. System identifies potential matches based on:
Expertise alignment
Availability overlap
Location compatibility
Preference matching
2. Notifies expert of potential match
3. Expert reviews project details
4. Expert indicates interest level
5. If interested, connection is made
6. Parties communicate via secure messaging
Use Case 4: Post-Collaboration Feedback
1. After each project (completed/failed), system sends survey to both parties for feedback 
2. Confidential rating submitted using 1 to 5 stars on various factors
3. Optional written feedback (comments)
4. Data stored and used to improve future matching (not publicly displayed)
5. Analytics updated
6. Matching algorithm refined
Use Case 5: Admin Monitoring
Admin logs in to monitor platform KPIs
Views dashboard
Identifies low success rates
Reviews feedback
Adjusts matching rules or flags issues

Tracking, Audit and Insights
The platform shall maintain detailed logs of relevant user interactions, transactions, workflow steps, and project lifecycle events for audit, reporting, and service improvement purposes. The platform shall provide dashboards and analytics for administrators, organizations, and experts, including metrics such as project submissions, successful collaborations, average time to match, completion rates, and user satisfaction. The platform shall also support short surveys, post-collaboration ratings, and confidential feedback to continuously improve matchmaking quality, user experience, and operational performance.

Surveys and Feedback Module
This is very important for trust and quality.
A. Platform Experience Surveys
Short surveys should be triggered at key moments:
after registration
after first project submission
after first match
after collaboration completion
occasionally after 3–6 months of usage
Example questions for organizations:
Was it easy to submit a project?
Did the platform help you find relevant experts?
How satisfied are you with the match quality?
How easy was it to communicate and organize the collaboration?
Would you use DZ-Bridge again?
What should be improved?
Example questions for experts:
Was profile creation easy?
Were project recommendations relevant?
Were organizations clear and responsive?
Were logistics and expectations well communicated?
Would you participate again?
What can be improved?
Use mostly:
1–5 rating scales
yes/no
multiple choice
one optional comment field
We should keep each survey short: about 4 to 8 questions.
B. Post-Collaboration Mutual Ratings
After a collaboration, both sides should be able to rate each other privately.
Organizations rate experts on:
expertise relevance
professionalism
communication
punctuality/reliability
overall value
Experts rate organizations on:
clarity of project scope
communication
logistics support
professionalism
overall collaboration quality
Each party can also add:
short comments
recommendation for future collaboration
flags/issues if something went wrong
C. Internal vs Public Visibility
Important design choice:
Most ratings/comments should remain internal at first
visible to admins and used by the matching engine
not publicly displayed until trust rules are mature
This avoids early tension and encourages honest feedback.
